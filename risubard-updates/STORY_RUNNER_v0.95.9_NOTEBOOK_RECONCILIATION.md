- 이번 진단: `memory` 요청 **0/7건**에서 해당 노트북 발견. v0.95.8 요청 분류 차단 수정 효과 확인.

- **오래된 '미해결' 항목 잔존**: 노트북 `Open threads`에 이미 진행된 만남의 실현 여부 같은 질문이 여전히 포함됨. 저장된 노트의 최신 응답 서명만 확인해도 과거부터 누적된 항목의 해결 여부는 검사되지 않기 때문.
- 또 하나의 정합성 오류: v0.95.8 소스는 `//@version 0.95.8`이지만 `const VERSION = "0.95.7"`로 내부 표시 버전이 오래되어 있었음.

## 수정 내용

1. **근거가 있을 때만 과거 미해결 항목 종료**:
   - 기억 읽기 모델에 `resolvedOpenThreads: [{index,evidence}]` 필드를 요청.
   - `index`는 이전 `openThreads` 항목의 0기준 위치.
   - `evidence`는 최신 **실제 저장된 소설** 또는 이전에 원문 근거가 검증된 `groundedEvents[].evidence`의 정확한 8자 이상 인용이어야 함.
   - 인용문이 어느 검증된 원문에도 없다면 기존 항목은 삭제하지 않음.
   - 메모의 반복된 동일 항목은 합치되, 서로 다른 질문을 임의로 합치지 않음.
2. **버전 동기화**: 공개 버전과 내부 상수 모두 `0.95.9`로 통일.
3. **기존 정보 보존**: 채팅 메시지, 캐릭터, 세계관 설정, 첫 메시지, 다른 플러그인, 사용자 저장 기억의 원본을 직접 편집하거나 일괄 초기화하지 않음.
4. **복구 지원**: 원본 v0.95.8을 `risubard-updates/archive/story_runner_v0.95.8.ts`로 보관.

## 제약

- 새 코드가 자동으로 모든 오래된 미해결 항목을 제거하는 건 아님. 실제 근거와 모델의 `resolvedOpenThreads` 출력이 모두 충족되는 항목부터 정리됨.
- 기존 저장 노트가 이미 최신 응답에 대응돼 있어 자동 재분석을 건너뛴다면, Story Runner의 `↻ 다시 읽기`를 이용해 확인 가능.
- 품질 영향은 수정 전후 동일 모델·동일 채팅 분기점·동일 사용자 입력으로 별도 비교해야 함.
- 현재 `1950~7000어절` 장문 설정과 Story Runner 이외 원본 프리셋은 이 릴리스에서 수정하지 않았음.
- Editor Lab 검토 요청이 `model` 모드로 발생한 것은 포착됐지만, 검토를 **DeepSeek**에 별도 지정했다는 증거는 없음. 모델 선정 기능은 그대로 유지.
