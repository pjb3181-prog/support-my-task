# Character Mixer v0.1.1 — B 이미지 태그 호환 수정

## 확인된 원인

- B 봇이 출력하는 이미지 토큰이 `{{img="hancock_angry"}}` 형태일 수 있음
- RisuBard 기본 렌더러는 `{{img::ASSET_NAME}}` 형태를 처리함
- Character Mixer v0.1.0은 가져온 B 에셋 이름에 충돌 방지 접두어를 붙여, 원래 토큰명과 실제 등록명이 달라질 수 있음
- 이미지 파일의 존재와 화면 출력은 별개: 파일이 있어도 태그 표기 또는 실제 사용 에셋명과 맞지 않으면 이미지가 표시되지 않음

## 변경 사항

1. `editdisplay` 플러그인 후크에 **표시 단계 전용 호환 처리** 추가.
2. `{{img="name"}}`, `{{img::name}}`, `{{emotion="name"}}` 등을 활성화된 Character Mixer 모듈의 이름으로 매핑.
3. v0.1.0이 이전에 생성한 편입 모듈도 소스 B 이미지 경로와 표시명으로 역추적하여 매핑. 다시 편입할 필요가 없도록 함.
4. v0.1.1이 새로 생성한 데이터 모듈에는 원래 에셋명과 등록된 별칭을 `assetAliases`로 보관.
5. A의 기존 동일 이름 이미지를 우선하고, B/C/D 사이에 같은 에셋명이 중복될 때는 하나를 임의로 선택하지 않음.
6. 기존 채팅 메시지와 원본 B 에셋 파일은 **수정하지 않음**.
7. Character Mixer 설정창 하단에 `Asset aliases (A chat)`을 표시하여, 원래 이름이 어떤 등록 이름에 대응하는지 확인 가능.
8. 플러그인 제거 시 표시용 후크도 정리.

## 설치 및 확인

1. 업데이트 전 RisuBard 데이터를 백업. 기존 채팅 복제본에서 시험 권장.
2. Character Mixer 0.1.1을 업데이트 또는 같은 플러그인 재설치.
3. 현재 A 채팅을 열어 `{{img="hancock_angry"}}`가 있는 응답을 다시 표시.
4. 변경이 없으면 Character Mixer 설정 하단 `Asset aliases (A chat)`에서 `hancock_angry`가 연결되어 있는지 확인.
5. 목록에 없으면 B의 해당 이미지가 **추가한 모듈의 assets에 포함됐는지** 확인하고, 필요한 경우 B 에셋 모듈에 체크한 후 `현재 채팅에 B 추가/업데이트` 실행.
6. 이름 연결은 됐지만 실제 이미지 파일이 비어 있거나 다른 저장소에 있는 경우 표시할 수 없음.

## 검증 및 한계

- 기존 6개 회귀 테스트와 별도 에셋 호환 테스트 10개
- JS 문법 검사, GitHub Actions 검증
- 실제 사용자 RisuBard의 이미지 렌더링·캐시·모바일 환경은 설치 후 확인 필요
- 사용자의 채팅 기록에서 모델이 생성한 잘못된 태그 자체를 영구 수정하지 않고 표시 단계에서만 바꿈
