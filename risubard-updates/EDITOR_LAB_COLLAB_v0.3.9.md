# Bard Editor Lab v0.3.9 — Writer ↔ Editor Collaboration

## 목표 및 범위

기존 Bard Editor Lab v0.3.8의 플러그인 이름(`bard_editor_lab`), 저장소 키, 자동 퇴고 이력, 원본 백업/복원, 문체 기준선, 장면 브리핑, Story Runner 감시, 기존 설정과 프리셋을 보존한 **선택형 추가 기능**.

- 작가: RisuBard의 메인 모델 (`model`) — 현재 힘오이 설정
- 편집자: 기존 보조 모델 (`otherAx`) — 현재 DeepSeek 설정
- 과정: 최초 생성 → DeepSeek 전체 진단 → PASS면 종료, 아니면 힘오이 정확한 구간만 수정 → DeepSeek 변경 구간 재검토 → 승인 시 채택
- 최대 0~3회 교정, 누적 교체율·문제 구간·검토 확신도·추가 시간 예산 설정 가능
- 본문 전체 재작성 대신 정확한 `before`/`after` 패치, 상태·화자·캐릭터 태그·숫자·기존 대사 보호
- 실시간 출력은 먼저 완료. 협업은 출력 이벤트 후 별도로 처리하며, 사용자가 다음 턴으로 진행하면 늦은 교정은 적용하지 않음
- 승인된 교정이라도 채팅 변경 전 원문 전체를 백업. 이전 원문 복원 기능 유지
- 일반 '선택적 퇴고' 및 '저비용' 모드 유지. 새 협업 모드에 들어갈 때만 확장된 호출 사용

## 사용법

1. RisuBard에서 기존 모델 설정을 확인: 메인=힘오이, 보조=DeepSeek.
2. Bard Editor Lab 설정 열기. **새 플러그인을 추가 설치하지 않고 같은 플러그인의 업데이트 사용**.
3. '자동 퇴고 ON', '생성 후 편집장 모델 검수 ON' 활성화.
4. 상단 검토 모델을 `otherAx`(보조)로 선택하고 모드를 `협업 · DeepSeek 검토 → 힘오이 부분 수정`으로 선택.
5. 새 협업 설정에서 '수정 작가=메인 모델', '품질/속도=균형'으로 선택.
6. 기본값: 최대 2회 수정, 추가 60초 예산, 누적 교체 20%, 검토당 3곳, 최소 확신도 75%.
7. 원고를 생성하면 기존 화면에 먼저 초안이 나옴. 검토가 끝나면 필요한 경우에만 교정본이 반영됨.
8. 결과는 Bard Editor Lab '최근 자동 퇴고 결과'에서 확인. 문제가 있으면 '가장 최근 퇴고 원본 복원' 클릭.

## 성능 주의사항

- 협업 모드 최초 검토는 DeepSeek에 원고 전체를 보내야 함. 이후 수정은 짧은 인용 구간과 전후 맥락만 전달.
- 독립 요청이 아니라 **의존하는 요청**이므로 최대 1 + 2×교정 횟수의 순차 모델 호출. 두 모델이 메모리에 로드되어 있어도 동시 추론을 보장하지 않음.
- 추가 시간 예산 초과 후에는 새로운 퇴고를 시작하지 않으며, 이미 승인된 후보가 있다면 그것만 유지. API 타임아웃은 실행 중인 모델 계산 취소를 보장하지 않음.
- 장면 브리핑의 '새 응답 완료 시 자동 분석'은 별도 모델 호출을 사용하므로 필요하지 않으면 OFF 권장.
- 18,000자를 넘는 생성물은 기본 최대 입력 제한 때문에 교정에서 제외될 수 있음. 옵션 변경 가능.
- 정확한 인용을 찾지 못하거나 안전 검증에 실패할 때는 **원문을 보존**함.

## 기술 검증

- Node 22의 `node --check`로 플러그인 전체 JavaScript 문법 검사
- 모의 RisuBard API를 통한 POST-save, PASS, 1회·2회 패치, 재검토 거절, 보호 태그, 채팅 전환 시 원본 보존, 중복 이벤트, 설정 UI·저장 테스트
- GitHub Actions workflow `.github/workflows/editorlab-collab-check.yml`
- 이 검증은 **실제 사용자의 RisuBard/Ollama 실행 환경을 재현한 통합 검증이 아님**. 모델 슬롯, 플러그인 API, 스트리밍 제공자에 따라 현장 시험이 필요.
