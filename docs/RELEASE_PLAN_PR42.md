# PR #42 배포 준비 계획

상태: **버전 번호 적용 완료(PR #42 브랜치), 보존 태그 `plugins-pre-pr42` 푸시 완료. `main` 병합과 자동 업데이트 배포는 아직 하지 않았다(최종 확인 대기).** RisuBard 본체·BardWiki, 설치본, 사용자 데이터는 변경하지 않았다.

## 1. 최종 변경사항과 설치본 대비 보존 (재확인, 브랜치 `7773960`)
- 플러그인 자동 테스트 **211개 통과, 실패 0.**
- 설치본(`analysis-quality`)의 함수 목록 대비: Story Runner 260개, Mutation State Router 264개, Bard Editor Lab 70개 **모두 저장소에 존재(누락 0).** (World Editor Lab은 설치본에 없던 신규 플러그인.)
- `main`(`3a8decb`)과 설치본의 플러그인 버전은 같다(0.95.9 / 0.79.5 / 0.3.10 / 0.1.1). 이 PR로 코드가 바뀌므로 버전을 올려야 자동 업데이트가 감지한다.
- 변경 파일(플러그인): `story_runner.ts`, `mutation_state.ts`, `bard_editor_lab.js`(+`bard_editor_lab_v0.3.10.ts` 사본), `world_editor_lab.js`(+`World_Editor_Lab_v0.1.1.ts` 사본). 나머지는 테스트·문서·실앱 테스트 도구.
- 플러그인 ID(`//@name`)와 업데이트 URL(`//@update-url`, `main`의 raw 파일)은 **그대로 유지**한다.

## 2. 버전 변경안 (아직 적용하지 않음)
호스트는 `//@version`을 `.`로 나눠 숫자로 비교한다(`compareVersions`). `0.95.10 > 0.95.9`이므로 아래 안은 모두 "더 높은 버전"으로 인식된다.

| 플러그인 | 현재 | 제안 | 수정 위치 |
|---|---|---|---|
| story_runner | 0.95.9 | **0.95.10** | 파일 머리 `//@version`, 소스 내 `const VERSION` |
| mutation_state_router_v2 | 0.79.5 | **0.79.6** | 파일 머리 `//@version`, 소스 내 `const VERSION` |
| bard_editor_lab | 0.3.10 | **0.3.11** | 머리 `//@version`, 화면 문구 2곳(`v0.3.10`), 사본을 `bard_editor_lab_v0.3.11.ts`로 |
| world_editor_lab | 0.1.1 | **0.1.2** | 머리 `//@version`, 화면 제목 `v0.1.1`, 사본을 `World_Editor_Lab_v0.1.2.ts`로 |

함께 고칠 테스트(버전 문자열 고정): `world_editor_lab.test.cjs`의 `@version 0.1.1` 정규식, `integration_hooks.test.cjs`의 사본 파일명 2곳. 변경 설명 문서는 기존 관례(`STORY_RUNNER_v…md` 등)에 맞춰 플러그인별 1개 추가.

확인된 제약: 호스트는 `//@version`이 파일 앞 500바이트 안에 있어야 한다. 현재 네 파일 모두 84~127바이트로 안전. 업데이트 URL은 `https`여야 한다(현재 충족).

## 3. 자동 업데이트 호환성
호스트 소스(`plugins.svelte.ts`)와 격리 실앱 관찰에 근거:
- **같은 ID로 교체:** 업데이트는 `//@name`이 같은 항목을 교체한다. 이름이 바뀌면 거부된다 → 이름은 불변.
- **설정·데이터 보존:** 플러그인 설정과 상태는 `pluginStorage`에 저장되고 업데이트가 건드리지 않는다. 이번 변경이 추가한 저장 키는 `risubard_editorial_receipt_v1:<chatId>` 하나뿐이고(영수증/검수 예정 표시), 기존 키·접두사는 그대로다. `//@arg` 선언이 없어 `realArg`도 비어 있다.
- **권한 팝업 재표시:** 스크립트가 바뀌면 호스트가 채팅 교체 등 권한을 다시 묻는다(실앱에서 확인). 사용자가 "예"를 눌러야 동작한다.
- **주의(호스트 동작):** 업데이트는 항목을 `enabled: true`로 다시 만든다. 사용자가 꺼 둔 플러그인은 업데이트 후 켜진다. 알리고 진행해야 한다.
- **부분 업데이트(순서 무관):** 네 개를 한 번에 받지 않아도 된다.
  - Story Runner 신 + Bard 구: Bard가 "검수 예정"을 모름 → 구 동작(중복 퇴고 가능, 데이터 손실 없음).
  - Bard 신 + Story Runner 구: 예정 표시가 없으므로 영수증 비교만 사용(구 동작).
  - 영수증 레코드의 새 `state` 필드는 구 Bard가 무시한다(서명이 없으면 퇴고를 진행). 구 Story Runner가 쓴 영수증(`state` 없음)은 신 Bard가 "검토 완료"로 취급한다.
  - Mutation, World Editor Lab은 서로·다른 플러그인과 독립. Story Runner ↔ Mutation의 `allowed-ipc` 선언은 변경 없음.
- **미검증:** 호스트의 "업데이트 확인→설치" 자체는 `https` 원격 URL이 필요해 로컬 격리 환경에서 재현하지 못했다. 배포 전후 검증은 6단계(아래)로 대체한다.

## 4. 플러그인별 변경 내역 (설치본 대비)
**Story Runner (0.95.9 → 0.95.10)**
- 훅 가드: 호출 토큰이 있는 요청과 보조 모드 요청은 건드리지 않음.
- 스트리밍 응답도 최고 품질 재작성: 출력 리스너에서 비평가/재작성을 한 번만 실행하고 한 번만 저장(저장 직전 본문이 같을 때만). 일반 응답은 기존처럼 `afterRequest`.
- 상태 표식 정리를 스트리밍에도 적용. 4분 제한: 비평가/재작성이 응답하지 않으면 원문 유지.
- 검수 영수증(기존 설치본 기능 유지) + "검수 예정" 표시(Bard와의 순서 경쟁 해소).
**Mutation State Router (0.79.5 → 0.79.6)**
- 요청 훅이 보조 모드·내부 호출 요청을 건드리지 않음, 세계 정본 범위 정리 결과를 실제로 적용.
**Bard Editor Lab (0.3.10 → 0.3.11)**
- Story Runner 영수증/예정 표시가 있으면 같은 원고를 다시 퇴고하지 않음. 상태 표식이 있어도 원문 비교가 일관됨. 협업 시드 대기 5초 제한, 내부 호출·협업 중 요청 가드.
**World Editor Lab (0.1.1 → 0.1.2)**
- 모델 호출: 플러그인 모델 차단 시에만 1회 재시도, 응답 없음 120초 제한, 빈 응답·끊긴 스트림 거부.
- 적용·복원: 쓰기 직전에 카드와 Mutation 잠금을 다시 확인(이전 상태로 덮어쓰지 않음).

## 5. 이전 버전으로 되돌리기
호스트는 **원격 버전이 더 높을 때만** 업데이트를 제안한다. 그래서 롤백은 "옛 코드 + 더 높은 번호"여야 한다.
1. **병합 전 보존:** `main`(`3a8decb`)에 태그 `plugins-pre-pr42`를 만든다. 옛 코드의 기준이다. (Bard 0.3.10, WEL 0.1.1 사본은 저장소에도 있음.)
2. **배포 롤백(전체):** 태그의 네 파일을 가져와 버전만 한 단계 더 올려(예: 0.95.11 / 0.79.7 / 0.3.12 / 0.1.3) `main`에 커밋 → 사용자가 업데이트하면 옛 동작으로 복귀. 단순 `git revert`만으로는 번호가 내려가 업데이트가 감지되지 않는다.
3. **개별 사용자 즉시 복구:** 플러그인 설정에서 해당 파일(태그의 옛 버전)을 직접 가져오기. 같은 이름이면 교체 확인창이 뜬다. 사용자 설치본의 기존 복구 스크립트(`analysis-quality/restore.cjs`)와 백업(`backups/narrative-quality-20261106/`)도 그대로 있다(수정하지 않음).
4. **데이터:** 새 버전이 만든 것은 영수증 키뿐이며 옛 버전은 무시한다. 롤백 후 정리할 데이터는 없다.
5. **롤백 기준(제안):** 배포 후 채팅이 멈추거나, 메시지가 사라지거나, 권한 팝업 이후에도 훅이 동작하지 않는 보고가 있으면 2번 실행.

## 6. 실행 순서 (승인 필요 단계 표시)
0. **사전 확인(완료):** 테스트 211개 통과, 설치본 함수 보존, 플러그인 이름·URL 불변, 헤더 500바이트 이내.
1. `plugins-pre-pr42` 태그 생성 *(승인 후)*.
2. PR #42를 Draft 해제 → 리뷰. 이 단계에서 병합하지 않는다.
3. **버전 변경 커밋**을 PR #42 브랜치에 추가(2절 표, 테스트 문자열·사본 파일명·변경 문서). *(승인 후)* 이후 테스트 전체 재실행, 헤더 바이트 재확인.
4. 최종 승인 → **`main` 병합**. 업데이트 URL이 `main`의 raw 파일이므로 병합 = 배포 시작이다. 네 플러그인이 한 번에 나가므로 병합 시점을 정한다.
5. 병합 후 약 5분(raw 캐시) 기다린 뒤 네 URL의 `//@version`이 새 값인지 확인.
6. **배포 후 검증(격리 새 인스턴스):** 이전 버전을 먼저 설치한 뒤 호스트의 업데이트 버튼으로 새 버전으로 갱신 → 같은 이름 교체, 설정 유지, 권한 팝업 후 동작, 일반·스트리밍 1턴을 확인. *(실제 설치본은 이 확인 후 사용자가 직접 업데이트)*
7. 사용자 실제 설치본 업데이트(사용자 승인): 업데이트 후 꺼 둔 플러그인이 켜졌는지 확인, 권한 팝업 허용.
8. 문제 발생 시 5절 2번(상향 번호 롤백).
